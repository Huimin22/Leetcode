## 1. Problem

291. Word Pattern II locked

Given a pattern and a string str, find if strfollows the same pattern.

Here follow means a full match, such that there is a bijection between a letter in pattern and a non-empty substring in str.

Example 1:

Input: pattern = "abab", str = "redblueredblue"
Output: true
Example 2:

Input: pattern = pattern = "aaaa", str = "asdasdasdasd"
Output: true
Example 3:

Input: pattern = "aabb", str = "xyzabcxzyabc"
Output: false
Notes:
You may assume both pattern and str contains only lowercase letters.

## 2. Summary

## DFS Breakdown

Define function: `dfs(p_idx, s_idx)`

* `p_idx`: current index in `pattern`
* `s_idx`: current index in `s`

---

### 3.1 Base Case

* If `p_idx` reaches end **and** `s_idx` reaches end → return `True`
* If only one reaches end → return `False`

---

### 3.2 Current Character

```python
c = pattern[p_idx]
```

---

### Case A: Character already mapped

* Get mapped string: `mapped = map[c]`
* Check if `s` starting at `s_idx` matches `mapped`

  * If yes → recurse `dfs(p_idx + 1, s_idx + len(mapped))`
  * If no → return `False`

---

### Case B: Character not mapped yet

* Try all possible substrings:

```python
for end in range(s_idx + 1, len(s) + 1):
    candidate = s[s_idx:end]
    if candidate not in used:
        map[c] = candidate
        used.add(candidate)
        if dfs(p_idx + 1, end):
            return True
        del map[c]
        used.remove(candidate)
```

## 3. Key Points

**DFS Template (Pattern → String Matching)**

* If current pattern char has no mapping:

  1. Try every substring starting at `s_idx`.
  2. Skip if substring already used.
  3. Map char → substring, mark used.
  4. Recurse to next pattern char.

     * If recursion returns True → return True.
     * Else → backtrack (remove mapping and mark unused).
  5. If all substrings fail → return False.

**Idea:** Only accept a mapping if the **entire remaining pattern** matches the remaining string.

* **map** → ensures **one character maps to a fixed substring**
  
* **used** → ensures **different characters map to different substrings**

* Why the used set is mandatory
When the code attempts to map a character c to a specific word, it faces two scenarios:

Forward Check: If character c is already in the mapping dictionary, we must check if the current word is identical to the previously stored mapping[c].

Backward Check (used's role): If character c is new, but the word it wants to "claim" has already been claimed by another character, the mapping is invalid.

A Straightforward Example
Suppose pattern = "ab" and s = "xyzxyz".

Step 1: Process character 'a'

We slice the string and pick word = "xyz".

mapping becomes {'a': 'xyz'}.

used becomes {'xyz'}.

Step 2: Process character 'b'

We attempt to slice and pick word = "xyz".

The program checks if word in used:.

It finds that "xyz" is already in the used set!

This means another character (in this case, 'a') has already occupied this string.

'b' must "shake its head" and skip this word, moving on to try a longer slice (e.g., "xyzx", and so on).

## 4. Code Implementation:


```
class Solution:
    def wordPatternMatch(self, pattern: str, s: str) -> bool:
        mapping = {}
        used = set()
        
        def dfs(p_idx, s_idx):
            if p_idx == len(pattern) and s_idx == len(s):
                return True
            if p_idx == len(pattern) or s_idx == len(s):
                return False
            
            c = pattern[p_idx]
            if c in mapping:
                mapped_str = mapping[c]
                if not s.startswith(mapped_str, s_idx):
                    return False
                return dfs(p_idx + 1, s_idx + len(mapped_str))
            else:
                for end in range(s_idx + 1, len(s) + 1):
                    candidate = s[s_idx:end]
                    if candidate in used:
                        continue
                    mapping[c] = candidate
                    used.add(candidate)
                    if dfs(p_idx + 1, end):
                        return True
                    del mapping[c]
                    used.remove(candidate)
                return False
        
        return dfs(0, 0)   


```

### Comparison of DFS Styles

#### 1. Classic Backtracking (`path.append`)
* **State Dependency:** **Path-Dependent**. The logic relies on historical choices stored in the "path." The result is only finalized when you reach the end of the string.
* **Repetitive Computation:** **High**. It is very difficult to use memoization because even if you are at the same `start` index, your `path` might be different, making the state hard to cache.
* **Return Value:** **None**. It typically operates by modifying a global result list or a shared object.
* **Best Use Case:** When you need to find a single path, or when the history of how you got to a node matters (e.g., Permutations).

#### 2. Divide & Conquer / Result-Returning (`for sub in dfs`)
* **State Dependency:** **Position-Dependent**. The result depends **only** on the current `start` index. What happened before `start` does not change what is possible after `start`.
* **Repetitive Computation:** **Low**. It is **perfect for Memoization**. Since the suffix results for a specific `start` index are always the same, you can store and reuse them.
* **Return Value:** **List (e.g., `List[str]`)**. Each function call returns a full package of all possible valid "suffix" combinations.
* **Best Use Case:** When you need to collect all possible combinations and the subproblems overlap significantly (like Word Break or Palindrome Partitioning II).

---

### Why this fits Word Break II
In this problem, the "remainder" of the string from a certain index is a standalone subproblem. By using the **Result-Returning** style:
1.  **Isolation:** `dfs(end)` focuses purely on solving the rest of the string.
2.  **Combination:** The parent call takes that "package" of results and simply prefixes its own `word` to every item in that package. 
3.  **Efficiency:** The `memo` acts like a save-point. If the recursion ever hits the same `start` index again via a different path, it doesn't re-calculate; it just hands over the pre-packaged list.
