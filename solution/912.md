## 1. Problem

912. Sort an Array

## 2. Summary

```
QuickSort (LC 912)

1. Base
if left >= right: return

2. Pick pivot
pivot = nums[random.randint(left, right)]

3. Two pointers
i = left
j = right

4. Partition
while i <= j:
    while nums[i] < pivot: i += 1
    while nums[j] > pivot: j -= 1
    if i <= j:
        swap(nums[i], nums[j])
        i += 1
        j -= 1

5. Recurse
quickSort(left, j)
quickSort(i, right)
```

## 3. Key Points

```
pivot fixed
i scans from left
j scans from right
swap wrong-side elements
after loop:
[left..j] <= pivot
[i..right] >= pivot
recurse both sides
```

## 4. Code Implementation:

```
class Solution:
    def sortArray(self, nums: List[int]) -> List[int]:
        def quickS(left, right):
            if left >= right:
                return
            i, j = left, right
            pivot = nums[random.randint(left, right)]
            while i<=j:
               
                while nums[i] < pivot:
                    i += 1
                while nums[j] > pivot:
                    j -= 1
                if i <= j:
                    nums[i], nums[j] = nums[j], nums[i]
                    i += 1
                    j -= 1
            quickS(left, j)
            quickS(i, right)
        quickS(0, len(nums) - 1)
        return nums  
```

## 5. Complexity Analysis
    Time：O(n)
        
    Space: O(1)

**"The efficiency of quicksort depends on the balance of the partitions. If each partition is evenly balanced, the recursion depth is reduced to log n, resulting in an overall time complexity of O(n log n). If the partitions are unbalanced, the recursion depth can approach n, causing the total complexity to degrade to O(n²). Randomly selecting the pivot probabilistically ensures that each partition is approximately balanced, thereby avoiding the worst-case scenario."**

## 8. Note

```
QuickSort Mistakes

1. Thought i and j must be adjacent.
   Actually j < i is enough.

2. Confused partition invariant.
   Not: left side strictly < pivot, right side strictly > pivot.
   Correct:
   [left..j] <= pivot
   [i..right] >= pivot

3. Misunderstood pivot position.
   Pivot value is used for comparison, not fixed index.

4. Thought middle area must be pivot.
   Actually values between j and i can be = pivot.

5. Wanted to use <= or >= in inner loops.
   Should use:
   while nums[i] < pivot
   while nums[j] > pivot
   Otherwise pointers may not move → infinite loop.

6. Thought swap might be useless when nums[i] == nums[j].
   Swap still forces pointer movement.

7. Confused pivot selection with pointer movement.
   Pivot chosen once per partition.
   i/j move to perform partition.

8. Placed pivot selection inside while loop.
   Pivot must be fixed before partition.

9. Thought recursion must include pivot area.
   Partition already guarantees correct side placement.
   Only recurse [left..j] and [i..right].

10. Didn't initially understand why random pivot helps.
    Randomization avoids consistently unbalanced partitions → prevents O(n²).
```

**Second**

1. **Pivot selection mismatch:** You pick a random pivot value, but do not track its index. Swapping based on value can fail if duplicates exist.
2. **Swap condition too strict:** `if i < j and nums[i] > pivot and nums[j] < pivot:` may skip necessary swaps, leaving elements on the wrong side. Standard quicksort just swaps when `i <= j`.
3. **`return nums` inside recursion:** Returning `nums` inside the recursive `quicks` function is unnecessary; quicksort sorts in place.
4. **Function doesn’t return anything outside recursion:** Your outer `sortArray` never returns the sorted list because `quicks` return value isn’t used.

**Third**

1. Used non-existent attribute: nums.random; should use random.randint and index nums.
2. Missing import for random.
3. Recursive calls missing parameter: quickS(left, j) → quickS(nums, left, j).
4. Wrong right boundary: used len(nums) instead of len(nums) - 1.
5. Wrong swap condition: used i < j; should be i <= j to avoid infinite loop when i == j.
6. Misunderstood purpose of i <= j: needed to guarantee pointer movement (i++, j--), not for meaningful swap.
7.  pivot = nums[random.randint(left, right)] generate random int.

**Fourth**

* Base case: used `left == right` instead of `left >= right` → misses empty subarrays after pointers cross.
* Partition: used `i < j` instead of `i <= j` → infinite loop when i == j or duplicate pivot.
* Recursive calls: swapped `quickS(nums, left, i)` / `quickS(nums, j, right)` → may overlap; correct is `quickS(nums, left, j)` / `quickS(nums, i, right)`.
* Returning value from `quickS` → unnecessary, QuickSort is in-place.
* Pivot selection inside loop → inefficient; should pick once per partition.
* Didn’t account for pointers moving past subarray → risk of empty subarray / out-of-bounds.

**Fifth**

* Inner `while i <= j` used instead of `if` → infinite loop / no pointer movement
* Missing `i += 1` and `j -= 1` after swap → pointers stuck
* Partition loop structure wrong → should be two inner while + one if swap
* No boundary check in `while nums[i] < pivot` / `nums[j] > pivot` → potential index error
