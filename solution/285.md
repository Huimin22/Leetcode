## 1. Problem

285 Inorder Successor in BST
    
## 2. Summary

**BST Inorder Successor – Core Idea**

* Inorder traversal of a BST is sorted
* Successor = smallest node greater than p

---

### Case 1: p has right subtree

* Successor is in right subtree
* Go right once, then keep going left
* Result = leftmost node in right subtree

---

### Case 2: p has no right subtree

* Successor is in ancestors
* Start from root and search:

Rules:

* If p < cur → cur is a candidate, move left
* If p ≥ cur → move right
* Last recorded candidate is the successor



**Key**

* BST property → decide direction
* always try to find smallest > p

**Iterative**

```
res = None
cur = root
while cur:
    if p.val < cur.val:
        res = cur
        cur = cur.left
    else:
        cur = cur.right
return res
```

## 3. Key Points

In a BST, we perform a **pruned search**, only following paths that could lead to the answer.

At each step:

* If `p < cur` → `cur` is a valid candidate → record it, then go left to look for a smaller valid candidate
* If `p ≥ cur` → `cur` cannot be the answer → go right

The loop ends when:

* All possible paths that could contain a node > p have been explored
* `res` stores the smallest “upper bound” seen along the way
* `cur` becomes `None` (no more nodes to visit)

One-line summary:
👉 “Instead of traversing all nodes, we move through the BST by narrowing the search space based on comparisons until no better candidate exists.”

## 4. Code Implementation:


```
class Solution:
    def inorderSuccessor(self, root, p):
        res = None
        cur = root

        while cur:
            if p.val < cur.val:
                res = cur
                cur = cur.left
            else:
                cur = cur.right

        return res   


```

    Time：O(n)
        
    Space: O(1)
