## 1. Problem

111. Minimum Depth of Binary Tree

## 2. Summary

MinDepth Binary Tree

DFS postorder:
- if node == null → 0
- compute left, right

Case:
- if one child is null → must take the other side (no min)
- return left + right + 1

- if both exist → return min(left, right) + 1

Key:
cannot use min(left, right) when one side is 0 (not a real leaf path)

## 3. Key Points

This line:

```python
if not root.left or not root.right:
    return left + right + 1
```

is **not just because one side is empty**, but because it uses a **clever property**.

---

### 🔑 Key idea

When one side is `None`:

```python
minDepth(None) = 0
```

So:

```python
left + right
```

👉 effectively equals **the depth of the non-empty side**

---

### 📌 Example

**Case 1: left is None, right is not**

```python
left = 0
right = 3
```

```python
left + right + 1 = 0 + 3 + 1 = 4
```

👉 same as:

```python
right + 1
```

---

**Case 2: right is None, left is not**

```python
left = 2
right = 0
```

```python
left + right + 1 = 2 + 0 + 1 = 3
```

👉 same as:

```python
left + 1
```

---

### ❗ Why not use `min`?

If you write:

```python
min(left, right) + 1
```

Then in a one-sided case:

```python
min(0, 3) + 1 = 1   ❌
```

👉 Wrong because it picks `0` (the non-existent path)

---

### ✅ So the real meaning is:

```
If one side is empty:
    return (depth of the non-empty side) + 1
```

Using `left + right` just avoids extra if-else logic.

---

## 4. Code Implementation:

```
class Solution:
    def minDepth(self, root: Optional[TreeNode]) -> int:
        if not root:
            return 0
        
        left = self.minDepth(root.left)
        right = self.minDepth(root.right)
        
        if not root.left or not root.right:
            return left + right + 1
        
        return min(left, right) + 1   

```

    Time：O(n)
        
    Space: O(1)
