## 3. Key Points

**`curr_sum` = current cumulative sum**
Each DFS level passes it down, representing the total sum accumulated from the root to the current node.
It acts as an **“abstract representation of the path”**, not an explicit list, but it effectively records the path information.

Example:

```text
nums = [1, 2, 3], target = 2

Chosen path: +1, -2, +3
path: ['+1', '-2', '+3']  # if we want to record each step
curr_sum: 0 → +1 → -1 → +2
```

* `curr_sum + nums[index]` or `curr_sum - nums[index]`
  is effectively **adding the current number to the running sum**, without storing each number in a list.
* If you only want to **count the number of valid ways**, `curr_sum` is enough; you don’t need to keep a `path`.
* If you want to **see the exact combinations**, then you use `path + [...]` to record each choice.

**Summary:**

* `curr_sum` = numeric representation of the path
* `path` = explicit sequence of chosen numbers

Both are essentially the same concept in different forms:

* One for calculation and checking,
* One for recording the actual choices.


## 4. Code Implementation:

```
class Solution:
    def findTargetSumWays(self, nums: list[int], target: int) -> int:
        n = len(nums)
        memo = {}
        
        def dfs(index, curr_sum):
            if index == n:
                return 1 if curr_sum == target else 0
            if (index, curr_sum) in memo:
                return memo[(index, curr_sum)]
            
            s1 = dfs(index + 1, curr_sum + nums[index])
            s2 = dfs(index + 1, curr_sum - nums[index])

            memo[(index, curr_sum)] = s1 + s2
            
            return memo[(index, curr_sum)]

        return dfs(0, 0)   


```
