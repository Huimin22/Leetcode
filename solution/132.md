## 1. Problem

132. Palindrome Partitioning II
    
## 2. Summary

partition DP

**Partition DP — General Template**

```text
dp[i] = optimal result for s[0:i]

For each i:
    for j in [0, i):
        if segment s[j:i] satisfies condition:
            dp[i] = min/max(dp[i], dp[j] + cost(j, i))
```

**Key idea:**
Enumerate the **last cut position `j`**, not the previous step.

**Use when:**

* Split / partition string or array
* Each segment must satisfy a condition
* Optimize (min/max) number of cuts / cost

**Mental model:**
“Where is the last cut before i?”


### 1. `pal[i][j]`: Precomputed Table (Auxiliary State)
This is a **2D Boolean array** used to store whether any given substring is a palindrome.

* **Meaning**: `pal[i][j]` is `True` if the substring `s[i...j]` (from index `i` to `j` inclusive) is a palindrome; otherwise, it is `False`.

---

### 2. `dp[i]`: Main DP State (Target Answer)
This is a **1D Integer array** used to track the minimum cuts required up to a certain point.

* **Meaning**: `dp[i]` represents the **minimum number of cuts** needed to partition the **prefix** of the string consisting of the first `i` characters (`s[0...i-1]`) into individual palindromic substrings.


Precompute palindrome table (interval DP)
pal[i][j] = (s[i]==s[j] and (j-i<=2 or pal[i+1][j-1]))

dp[0] = -1

for i in 1..n:
for j in 0..i-1:
if pal[j][i-1]:
dp[i] = min(dp[i], dp[j] + 1)

return dp[n]

## 3. Key Points

Precompute all palindromes in pal table.
Then use dp.
Iterate i from 1 to n.
For each i, try all cut points j.
If s[j:i] is palindrome, update dp[i] with the minimum dp[j] + 1.
Return the minimum dp[n].

Here is the English translation:

**Why must $i$ move backwards?**

In interval DP (such as finding the Longest Palindromic Substring), determining whether $dp[i][j]$ is a palindrome typically depends on a **shorter inner substring**, $dp[i+1][j-1]$.

When you are calculating the case for $i=0, j=1$ (e.g., "aa"), you need to already know the results for $i=1$.

Because your $i$ iterates backwards from $n-1$ down to $0$, by the time you reach $i=0$, all results for $i+1$ (i.e., 1, 2, 3...) have already been computed and stored in the $dp$ table. This is precisely why $i$ must be traversed in reverse order.

**Why enumerating all `j` won’t miss the optimal solution:**

```text
All possible last cut positions are j ∈ [0, i)

The optimal solution must make its last cut at some j in this range

So we try every possible j:
dp[i] = min over all j

→ This guarantees the optimal solution is considered
```

## 4. Code Implementation:


```
class Solution:
    def minCut(self, s: str) -> int:
        n = len(s)

        # 1. pre-process
        pal = [[False] * n for _ in range(n)]

        for i in range(n - 1, -1, -1):
            for j in range(i, n):
                if s[i] == s[j] and (j - i <= 2 or pal[i + 1][j - 1]):
                    pal[i][j] = True

        # 2. dp[i]: s[0:i] 
        dp = [float('inf')] * (n + 1)
        dp[0] = -1

        for i in range(1, n + 1):
            for j in range(i):
                if pal[j][i - 1]:
                    dp[i] = min(dp[i], dp[j] + 1)

        return dp[n]
  
```
