## 1. Problem

230. Kth Smallest Element in a BST
    
## 2. Summary

BST → inorder = sorted

use stack to simulate inorder

while cur or stack:
    go left (push all)
    pop → smallest
    count++
    if count == k: return
    go right


## 3. Key Points

👉
cur drives going down, stack handles going back up

as long as you can go down OR go back, don’t stop


## 4. Code Implementation:


```
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right
class Solution:
    def kthSmallest(self, root: Optional[TreeNode], k: int) -> int:
        stack = []
        cnt = 0
        cur  = root
        while stack or cur:
            while cur:
                stack.append(cur)
                cur = cur.left
            cur = stack.pop()
            cnt += 1
            if cnt == k:
                return cur.val
            cur = cur.right   


```


```
class Solution:
    def kthSmallest(self, root: Optional[TreeNode], k: int) -> int:
        self.cnt = 0
        self.res = None
        
        def dfs(node):
            if not node or self.res is not None:
                return    
            dfs(node.left)
            
            self.cnt += 1
            if self.cnt == k:
                self.res = node.val
                return 
    
            dfs(node.right)
            
        dfs(root)
        return self.res
```

## 8. Note

**Second**

* **Recursion's "Pop"**: You missed that recursion's "backtracking" is an **automatic pop** from the system call stack. It follows the same "Left-Root-Right" logic as your manual stack.
* **The `cur.right` Reset**: You didn't initially see that `cur = cur.right` triggers a **new search for the minimum** within that subtree. It forces the code back into the `while cur` loop to find the leftmost node.
* **Stack Dynamics**: You confused the push order with the pop order. Nodes are pushed along the left path (Largest to Smallest) specifically so they can be **popped in ascending order** (Smallest First).
* **Traversal Flow**: You thought the stack was filled once; it is actually a **dynamic "Push-Pop-Transition" cycle**. The stack acts as a breadcrumb trail to return to parents only after their entire left subtrees are processed.

### The Iterative Logic "Formula"

1. **Dive Left (`while cur`)**: Fill the stack until you hit the smallest node.
2. **Process (`pop`)**: This is the "In-order" moment to increment `cnt` and check `k`.
3. **Pivot (`cur.right`)**: Move to the right subtree. If it exists, **restart Dive Left**; if not, **continue Popping** from the existing stack.
