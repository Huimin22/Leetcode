## 1. Problem

91. Decode Ways
    
## 2. Summary

DP

dp[i] =

    + dp[i-1]   if s[i-1] != '0' //one digit if == 0
    
    + dp[i-2]   if 10 <= int(s[i-2:i]) <= 26 //two digit if in 10~26

## 3. Key Points

* corner case: s[0] == '0'
* '0' cannot stand alone
* Only combine 10~26 for two chars
* dp[0] = 1 as base for counting

No special case for n=1; handled by dp initialization.


## 4. Code Implementation:

```
class Solution:
    def numDecodings(self, s: str) -> int:
        if s[0] == '0':
            return 0

        n = len(s)
        dp = [0]*(n+1)
        dp[0] = 1
        dp[1] = 1

        for i in range(2, n+1):
            if s[i-1] != '0':
                dp[i] += dp[i-1]
            if 10 <= int(s[i-2:i]) <= 26 :
                dp[i] += dp[i-2]
        return dp[n]

```

## 8. Note

**Mistakes**

1. Wrongly special-cased n ≤ 1 or n ≤ 2
2. Initialized dp[0] as 0, breaking two-character combinations
3. Hardcoded dp[2] = 2, ignoring string content
4. Wrote `if s[0] == 0` instead of `s[0] == '0'`
5. Ignored base case handling for n=1 or n=0

**Second**

* Misunderstood dp[i] update: must **add** dp[j]+1 for all valid j, not just assign.
* Confused one-digit vs two-digit: one-digit cannot be '0'; two-digit handles 10 or 20.
* dp[0] represents empty string → must be 1, not 0.
* Returning dp[n-1] instead of max(dp) leads to incorrect LIS/Decode Ways results.

**Third**

Mixed up dp index and string index.

Defined `dp[i]` as length-based but updated it using string index logic.

Used `for i in range(1, n)` which misaligned dp and s mapping.

Accessed `dp[i-2]` when `i=1`, causing negative index (logic error).

Returned `dp[n-1]` instead of `dp[n]`.

Sliced `s[i-1:i+1]` while updating `dp[i]`, breaking length-index consistency.

Root issue: unclear definition — dp represents length, not character position.
