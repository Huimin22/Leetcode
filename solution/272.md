## 1. Problem

272 Closest Binary Search Tree Value II
     
Given a non-empty binary search tree and a target value, find k values in the BST that are closest to the target.

Note:

Given target value is a floating point.
You may assume k is always valid, that is: k≤ total nodes.
You are guaranteed to have only one unique set of k values in the BST that are closest to the target.
Example:

Input: root = [4,2,5,1,3], target = 3.714286, and k = 2

```
    4
    
   / \
   
  2   5
  
 / \
 
1   3
```

Output: [4,3]
Follow up:
Assume that the BST is balanced, could you solve it in less than O(n) runtime (where n = total nodes)?

## 2. Summary

BST inorder + deque(k)

Start with an inorder traversal (left → node → right), which gives values in sorted order.

Maintain a deque of size k:

* If res size < k → simply append current node value.
* If res size == k:

  * If current value is closer to target than res[0] (the farthest in the window):
    → pop left (remove res[0]) and append current value.
  * Else:
    → stop traversal early (prune), because all later inorder values will be even farther.

## 3. Key Points

Use inorder’s monotonic order + deque window to maintain k closest values, and apply pruning once the current value becomes worse than the current window boundary.


---

### Key idea:

The purpose of inorder traversal is to scan all candidate values in **sorted order (increasing stream)**.

Then:

* First, fill the deque with the first k elements.
* After that, continuously maintain a deque of size k by replacing worse candidates with better ones.
* The deque always stores the current **k closest values to the target**.

---

### Pruning (stopping condition):

We can stop traversal when:

> the current node is already worse than the “worst” element in the deque.

This is because:

* Inorder traversal produces values in **increasing order**
* However, the distance to the target is **not monotonic (it forms a U-shape)**

So once we enter the **increasing (right side of the U-shape)**:

* If the current value is already worse than the current window boundary,
* then all future values (which are even larger) will also be worse.

👉 Therefore, no future node can improve the current k-best result, so we can stop early.

---

### logic summary:

1. **Inorder property**

   * Produces values in increasing order
   * But distance to target is not monotonic

2. **Deque stores**

   * The current k closest values seen so far

3. **Pruning condition**

   * If current value is worse than `res[0]` (the worst in the deque)

4. **Why we can stop**

   * Because remaining inorder values are larger
   * And we are already on the increasing side of the U-shaped distance curve
   * So all future values will be even farther from the target


## 4. Code Implementation:

```
class Solution:
    def closestKValues(self, root, target, k):
        from collections import deque

        res = deque()

        def inorder(node):
            if not node:
                return

            inorder(node.left)

            if len(res) < k:
                res.append(node.val)
            else:
                if abs(res[0] - target) > abs(node.val - target):
                    res.popleft()
                    res.append(node.val)
                else:
                    return

            inorder(node.right)

        inorder(root)
        return list(res)   
```
