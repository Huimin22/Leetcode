## 1. Problem

51. N-Queens
    
## 2. Summary

For each row, try all columns:
    Check if col / diag1 / diag2 have conflicts
    If valid:
        path.append(current row's choice)
        dfs(next row)
        path.pop()  # backtrack
        
When the last row is reached, path length = n → record a complete solution

**Quick Notes for Memory:**

* DFS row by row.
* Each layer = a row. Choices = available columns.
* Conflict check: `col`, `row-col` (left diag), `row+col` (right diag).
* Append row string to path.
* Backtrack after DFS.
* Terminate at `row == n` → add path to results.


## 3. Key Points

* DFS row by row, each row place one queen.
* Choices per row = columns 0..n-1.
* Conflict check:

  * Column occupied → `col in cols`
  * Left diagonal → `row - col in diag1`
  * Right diagonal → `row + col in diag2`
* Place queen → mark `cols`, `diag1`, `diag2` → append row string to path.
* Recurse next row.
* Backtrack → unmark sets, pop path.
* Terminate at `row == n` → valid solution → save path.

## 4. Code Implementation:


```
class Solution:
    def solveNQueens(self, n: int) -> List[List[str]]:
        res = []
        cols = set()
        diag1 = set()
        diag2 = set()

        def dfs(path, row):
            if row == n:
                res.append(path[:])
                return 
            for col in range(n):
                if col in cols or (row-col) in diag1 or (row+col) in diag2:
                    continue
                cols.add(col)
                diag1.add(row-col)
                diag2.add(row+col)
                seg = "."*col + "Q" + (n-col-1)*"."
                path.append(seg)
                dfs(path, row+1)
                path.pop()
                cols.remove(col)
                diag1.remove(row-col)
                diag2.remove(row+col)


        dfs([], 0)
        return res  


```

* **Base Case Return**: You need a `return` after `res.append(path[:])` to stop deeper recursion once a valid board is completed.
* **Return Values**: `return False` is unnecessary. In a "Find All" DFS, the success is recorded by mutating the `res` list, not by passing booleans back up the stack.

---

### Why no `return False`?

1. **Goal is Exhaustion**: You are collecting **all** solutions, not just checking if one exists. The loop naturally finishes when all columns are tried; a boolean doesn't help the caller.
2. **Implicit Empty Result**: If no solutions are found, the `dfs` completes, and `res` remains an empty list `[]`. This is the standard way to represent "no answer" in these problems.
